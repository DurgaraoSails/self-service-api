# Local secrets

Everything under `secrets/` is gitignored — nothing here is ever committed. This directory holds
local-dev-only credentials that the app loads automatically when present, so you don't have to
re-export environment variables every session. In any environment where these files don't exist
(CI, prod), the app falls back to the equivalent environment variables.

## `jwt/private-key.pem`, `jwt/public-key.pem`

RSA key pair used to sign/validate self-issued JWTs. Generate with:

```bash
./scripts/generate-jwt-keys.sh
```

## `smtp.properties`

Despite the name, this is the general local-secrets properties file — anything imported here
becomes an ordinary Spring property, so it's grown beyond just SMTP. Not generated by a script —
create it yourself:

```properties
SMTP_USERNAME=you@gmail.com
SMTP_PASSWORD=your16charapppassword
BREVO_API_KEY=your-brevo-api-key
DB_PASSWORD=your-local-postgres-password
```

- `SMTP_USERNAME`/`SMTP_PASSWORD` — real email sending (`SmtpEmailService`, active outside the
  `local` profile). For Gmail: the address needs 2-Step Verification enabled, and
  `SMTP_PASSWORD` must be an [App Password](https://myaccount.google.com/apppasswords), not your
  regular account password.
- `BREVO_API_KEY` — read by `application.yaml`'s `brevo.api-key: ${BREVO_API_KEY}`
  (`RestClientConfig`).
- `DB_PASSWORD` — read by `application.yaml`'s `spring.datasource.password: ${DB_PASSWORD:postgres}`.
  Only needed if your local Postgres password isn't the `postgres` default (e.g. a native install
  instead of `infra/selfservice_db/compose.yaml`'s Docker Postgres, which sets it to `postgres`).

Loaded via `spring.config.import: optional:file:./secrets/smtp.properties` in
`application.yaml` — if the file is absent, all of the above fall back to the (empty-by-default,
except `DB_PASSWORD`) environment variables of the same name, so prod/CI deploys are unaffected.
